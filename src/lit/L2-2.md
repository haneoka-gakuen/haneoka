## 枢纽与依赖边界

`catalog-screen` 协调资源类型、跨服、筛选、详情、媒体和评论；`community-workspace` 协调读取、编辑、上传和状态；推荐动态及直接详情返回使用 `/community/feeds/`，社区根地址由拼贴入口持有。先沿相应职责追踪，不为缩短文件或画图拆分它们。

配队子控制器持有父组件上下文；类型回引用与运行时循环分别判断。共享 `catalog` 工具包含 HTTP、语言、服务器选择和展示格式，`src/lib` 的若干读取器反向引用它，不能将两个目录概括成严格上下层。

手动队伍的 Live 评分读取所选成员／留影的实际培养；全部卡牌范围只为未拥有的卡牌提供满培养输入。歌曲、演奏条件与未填写培养策略在“配队 → 手动队伍”设置；资料中的队伍页管理已保存队伍，并可转入手动配队或激奏选曲。队伍、培养、账户或评分条件改变会清空旧评估与换人建议并取消在途请求；替换队长的建议固定由替换成员担任队长。

激奏组队和激奏活动推荐共用自身 COMBO BONUS 下限设置；结果展示队伍倍率和另一项活动奖励。

与组队、活动收益平级的独立页签使用[激奏选曲控制器](team-builder/song-comparison.ts)串行请求当前 EngineClient，结果只接受单 Worker 正常最终返回；[视图](team-builder/song-comparison-view.ts)按歌曲分组并展开已选难度。计算任务由父组件的令牌互斥管理；改队伍、培养或演奏条件会取消计算，同一账户与资料身份内保留旧评分并标记条件已变；切换账户或资料身份清空当前评分。目标评级、有效人数和排序只重算派生指标。选择偏好写入 Box，评分缓存只驻留内存。页签复用队伍编辑器，可直接读取保存队伍；队伍编辑器、保存队伍卡片和配队结果均通过父组件 openSongComparison 跳转，不自动保存或开算。

连接时初始化、断开时清理事件／Worker／播放器；应用栏接管要恢复，旧异步结果要遵守已有取消和身份规则。验证入口见 [开发导航](../../docs/DEV_GUIDE.md)。

公开卡牌、留影、活动、歌曲页面由 `catalog-screen` 在可见时检查页面快照；异步详情模块先准备，版本复核后同步提交。新增实体壳不采用集合内嵌载荷，删除依据完整索引，计算结果按固定来源独立接管。

配队工作区以一行主页签容纳全部七个分区：配队、激奏竞技场、激奏选曲、活动收益、我的卡牌、账号加成与队伍；页签写入 `?tab=`，窄屏沿用共享横向滚动。配队页签的自动／手动方式位于条件面板顶部，窄屏位于条件摘要上方。[输入投影](team-builder/workspace-state.ts)迁移名次模式并保留选择草稿；[共享选卡器](team-builder/card-picker.ts)为手动队伍保留单卡选择，为活动加成卡提供全图鉴多选；[共享选曲器](team-builder/song-picker.ts)使用共用歌曲网格，直接提供当前显示结果的全选与全不选，另提供清空全部选择及撤销，在应用时提交选择，筛选不删除选择；按乐队／署名、歌曲分类、属性、激奏任务、等级及时长分组筛选，支持混合任务；JUST 与 CB 条件按有效选曲任务显示，隐藏草稿不进入请求身份。实际请求排除当前不可用谱面，结果保存请求与培养口径；活动检查点可附带展示范围，同身份下旧结果标记失效，资料或账号切换隔离结果。选曲元数据按目录固定来源缓存读取 song-meta，缺失不阻塞评分。

普通评分的演奏条件保留原作帧率；首帧、到期边界和提前教程沿用同一冻结请求。[手动评分适配](team-builder/manual-results.ts)冻结实际成员、留影、玩家和评分条件，逐曲结果与自动配队共用 [详情渲染](team-builder/results.ts) 的分数分布、所需综合力、技能顺序、时间线及提前击打教程。所选顺序分数与 120 种顺序的平均分分别展示；选择顺序不重新计算或改写平均分。顺序按手动阵容槽位保留，换队长或单槽替换仍沿用当前选择；打开其他保存队伍或清空阵容重置；自动结果转入时沿用所选顺序。基准独立复制评分及所选顺序，改条件后与当前队伍按同一条件重评；歌曲行按选曲顺序保持位置。

[工具布局](team-builder/tool-layout.ts)按实际内容宽度和高度切换：宽屏为不透明条件面板与结果列，二者占满内容区各自滚动；窄屏结果在前，条件以全屏面板打开，操作区固定在底部。首次计算前结果区显示步骤清单，每项缺失条件附带定位控件。条件面板内各分区以分隔线组成一张面板。选曲使用共享选择器的歌曲网格；时长读取失败可重试，匹配集合未完整判定时禁止批量替换。[结果指标](team-builder/result-metric.ts)统一卡片、导出与比较的数值口径；[比较状态](team-builder/result-comparison.ts)按账号和资料隔离最多三项快照，捕获自动／手动来源和所选技能顺序；新自动搜索清除旧自动结果，保留手动快照供跨流程比较，续算更新命中项并保留榜单外项。同谱面、同有效评分条件和指标单位才显示差值，成员、留影绑定与培养变化分别计数。桌面比较共享指标行，手机显示基准和一支可切换候选，切换候选不改变三项集合。

资源规划结果同时展示原请求的普通与挑战队伍，分别使用 Boost/CP 消耗；手动评估与综合力目标的显示计数由有效谱面投影生成。

工作区焦点滚动按实际任务栏与计算栏边界避让；模态选择器使用自己的滚动区域。各计算任务的结果定位均留出顶部任务栏空间。

断开时清理应用栏与提示定时器；断开后的异步更新不写入后续页面的应用栏，切换页签沿用各任务的滚动位置。我的卡牌复用目录卡片（`tile`），参与状态叠加在卡面右上角，批量操作集中在一个菜单。成长编辑器按游戏标记显示特训（1–5）、觉醒徽章与留影突破图标，等级可直接输入、步进或拖动。手动配队和激奏选曲共用队伍编辑器及工具布局：五列阵型位于主工作区，成员在上、留影在下，每列下方为带标签的“队长”与“推荐”控件；条件栏始终单列，手机端通过条件面板调整评分设置，队伍校验直接定位主工作区。工作区占满导航栏外的可用宽度；演奏、高级条件与结果详情复用共享折叠。结果分组独立于队伍卡片；每张卡按歌曲、指标、阵容、操作展示，歌曲封面与名称信息并排，歌曲属性以歌名前的图标呈现，难度与带圆形乐队图标的演唱者分组展示，不显示歌曲时长或重复输入设置。图片导出通过[页面快照](shared/team-result-image.ts)直接复用结果卡片的阵容顺序、成员与留影绑定及样式，排除操作按钮、折叠详情与养成叠层，通过 [结果视图](team-builder/results.ts) 从冻结的结果补全歌曲信息与全部成绩指标，附加站点 Logo、名称和网址；导出先加载整张结果卡的延迟图像；字体、图像与 SVG 图标内嵌，临时导出节点始终清理。

活动收益以“刷取推荐／资源规划”组织。刷取推荐独立保存玩法、判定、奖励目标和培养／回忆条件，旧推荐与奖励配队设置迁移后保持有效输入；满足既有 AP／已填写培养契约时沿用推荐检查点，否则使用自定义奖励搜索。切换流程保留旧结果快照并标记条件变化。手动配队独立选择普通或激奏评分，激奏评价和换人建议共用准确率、指定名次与固定种子数量。

刷取推荐的活动选择提供[手动条件](team-builder/manual-event.ts)，引用同服完整活动的结算表与加成档位，自选属性、乐队／角色和特殊成员／留影。手动模式仅投影普通 Live、激奏和跳过单次收益，隐藏挑战与 CP 折算而保留其草稿；资源规划仍使用正式活动。请求和结果快照携带实际效果，条件变化使旧结果与检查点失效。

[song-rules.ts](team-builder/song-rules.ts) 为竞技场、普通配队、活动收益和手动评价共用属性与三个区间控件；普通模式仅发送属性，激奏模式发送区间覆盖，原曲值为零。规则保存在请求和结果身份中。同一组件提供普通与活动配队的逐曲／多曲平均选择；联合结果展示各曲评分及收益，结果对比保留聚合方式。

LUCK 计算默认自动：评分与手动评价使用概率期望，对手分数仍只支持无 LUCK 谱面；活动收益使用固定 32 个种子。同一请求的全部候选读取同一已解析次数。自定义次数位于高级折叠，普通／竞技场与活动分别保留模式和次数草稿，自动切换不覆盖草稿；旧设置保留次数并迁移为自动，结果与导出读取冻结请求的实际整数。

理想 JUST 点按窗口在含 JUST 的普通配队、竞技场、活动收益和手动条件中共用数值控件；空值不限制，隐藏时保留草稿。实际请求只携带当前任务生效的窗口条件，不将上滑键的提前触发范围混入点按口径。

工作区按配队、激奏竞技场、刷取推荐、资源规划保存当前结果与条件，任务切换分别恢复滚动位置，账号或资料变化清空隔离缓存。CP 折算草稿不会因执行模式变化丢失；不兼容组合在提交前定位收益口径。字段错误定位具体控件；激奏选曲手机结果按歌曲展示主指标和可展开难度明细。运行状态读取 EngineClient 的资源／计算阶段。刷取推荐在本地核对培养和账号输入，技能程序兼容性由实际 Rust 请求校验，保留 TS 评分器的能力边界不作为培养缺失。

加载、恢复及修改配队条件时，当前已选的不超过四张谱面由 EngineClient 预取；下载复用请求内的固定来源缓存，不提前搜索队伍。

“我的卡牌”顶部提供日服／国际服切换与导入／导出入口，切换会先解绑旧卡库、取消旧任务与导入预览，再加载目标服独立卡库；导入弹窗保留截图、设备及备份来源，跨服预览在标题处显示复制方向，确认栏显示已选项目数量。

普通卡库的批量操作可清除当前服全部成员与留影的“必须使用”标记，包含筛选外的记录；操作复用本机撤销，不改变持有与参与搜索状态。

活动收益的 [reward-plan-view.ts](team-builder/reward-plan-view.ts) 使用共享分段控件显示主奖励、折算与同分顺序；结果标签读取返回方案，设置草稿通过领域 `reward-plan.ts` 编译。 刷取推荐在游玩模式下直接提供计入 CP 挑战收益入口；自动折算复用原生校准返回的挑战队伍，与普通／激奏队伍同时展示，养成和对比读取各自冻结请求。完整活动结果按账号、区服和资料身份保存在本机，刷新时恢复最新结果并保留当前设置草稿。

配队结果与手动评分通过[队伍养成对照](team-builder/team-growth.ts)进入同一模拟弹层，可勾选多项养成并选择升一阶或升满：先显示原队伍养成收益，再显示养成前后重新配队及额外收益。条件、候选与自动折算配置绑定结果快照；资源规划不提供单场养成入口。对照请求共用任务锁，取消保留候选与未完成状态，账号／资料切换关闭弹层；模拟不写卡库，优先级与详情复用完整引擎结果，自动 CP 随方案重新校准；材料与技能在详情内按需加载。
配队资料刷新按完整 release 身份复用已加载或静态内嵌的目录图标，避免替换计算 DTO 时清空卡面属性、特训和觉醒标记；目录图标保持同一 release 的地址。

[catalog-sort.ts](team-builder/catalog-sort.ts) 为卡库、手动及活动选卡器、所有选曲器复用图鉴排序项、比较规则和共享控件，排序控件随筛选面板展开显示；排序按成员、留影及歌曲在当前工作区分别保留，不改变选择和队伍顺序，歌曲指标读取同一固定来源的谱面统计。

号池区域提供现有日服游客身份导入，以及日服／国际服账号删除确认对话框；删除失败刷新版本，成功清空选择并显示 snackbar。

号池管理使用无字段的日服游客创建按钮和国际服邮箱／密码表单；国际服按邮箱合并三个区服，账号级登录覆盖三个区服，区域健康表也使用邮箱／游客名称，不再显示 JSON 录入表单。

激奏的[分区名次控件](team-builder/gekiso-rank.ts)由自动配队、手动配队、竞技场及固定队伍选曲共用；三个区间名次随请求、结果和比较保存。旧统一名次迁移为三个相同名次。养成模拟通过[通用选卡器](team-builder/card-picker.ts)在冻结候选池内选择成员或留影，沿用搜索、筛选和排序，不改实际卡库。

配队结果详情的时间线在后台读取，不占用工作区计算状态；折叠的前十技能顺序按展开挂载。评分详情及手动结果的单列内容使用共享 `stack--flex`，保留自然高度并避免多层 Grid 内在尺寸计算。手动配队仅在保留基准或替换建议时计算对应身份，展开详情不额外组装完整候选卡库。工作区高度在切换布局及 ResizeObserver 回调中测量，结果更新不强制读取布局；尺寸未变时不重复写入样式。

活动收益的共享奖励方案可选择平均或单次最高奖励；激奏评级支持房间人数、其他玩家平均分与单人 Mission。普通跳过保留 CP 目标及折算，结果与比较使用冻结方案；LUCK 的完成状态显示样本内最优。
