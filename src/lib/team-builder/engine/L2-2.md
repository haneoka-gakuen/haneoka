## 职责与当前调用链

当前 [界面](../../../lit/team-builder.ts) 创建 [EngineClient](client.ts)，通过 [Worker](worker.ts) 调用锁定的 Rust/WASM 引擎。WASM 由 [构建脚本](../../../../scripts/build/team-builder-engine.mjs) 从 `.dependencies/ournotes-team-builder` 编译到忽略的 `generated/`；引擎内部规则归独立仓库维护。

| 入口 | 责任 |
| --- | --- |
| [client.ts](client.ts) | 主线程请求、多 Worker 分片、进度与快照、取消时替换 Worker；页面空闲时只预热首个 Worker，按实际任务启动其余实例 |
| [worker.ts](worker.ts) | WASM 装载、release 数据句柄、固定身份的谱面读取、搜索／成长／评价／时间线消息；未评分时原生 null unknownCards 转为空数组 |
| [charts.ts](charts.ts) | 固定身份谱面的在途下载共享、限时重试、解压及四张共享载荷缓存；在途共享独立于长期缓存淘汰 |
| [protocol.ts](protocol.ts) | `EngineCall`、`EngineReply`、停止原因和快照契约 |
| [pt-eligibility.ts](pt-eligibility.ts) | 网页与保留 TS 路线共用的严格活动输入检查；按原生 64 位乘积边界校验，技能兼容性由当前原生请求最终判定 |
| [api.ts](api.ts) | 可序列化输入输出及 TS 评价／搜索实现；不能据此认为浏览器实际走 TS 计算 |
| [master.ts](master.ts)、[box.ts](box.ts) | Master 编译、成员与留影输入和成长状态 |
| [execution.ts](execution.ts)、[merge.ts](merge.ts) | 单一有效谱面的联合请求折叠、跨线程预算、完成度、结果比较与分片合并；单曲折叠保留页面草稿 |

`run` 的可选最终结果回调只用于单 Worker 路径，在合并快照和附加搜索停止标签前提供独立副本。快照、取消、排队超时及分片搜索不会触发此回调；固定队伍选曲据此区分完整评分与搜索候选。

`runBatch` 在同一任务队列内把独立场景分给现有 Worker 池，每个场景由一个 Worker 完整执行校准、加载与评分流程，不新增引擎实例。场景保留独立身份、预算、停止状态及原始结果顺序；单项停止只替换所属 Worker，整批取消中止全部在途任务。结果回调先保留已完成或部分场景，任一回调／执行失败后停止其他场景并等待它们结束，再释放队列。

`full/`、Live／Gekiso 与 `api.ts` 保留 TS 实现和类型。修改前先追实际调用者，不能把这些实现、上层 `solver/` 和当前 WASM 路线混为同一个执行入口。

复合技能条件沿用成功子条件的触发时间：AND 取有效时间最大值，OR 取首个成功分支；失败和重新检查清除旧时间。Rust 主路径与保留的 TS 实现使用相同规则。

COMBO 区间首批同刻的独立 Tap／Flick 按相邻两帧交付，保留名义时间、判定和区间归属；后一帧须仍在区间内且满足各音符的基础 Perfect 窗口。链式音符、自动计数和其他区间沿用原判定流。

## 状态、失败与验证

可选 `minJustWindowMs` 是 JUST 普通点按在开段技能生效后的双向窗口下限，沿用实际等级和持续时间；未设置时保持原搜索。普通激奏、竞技场、多曲平均和活动收益在候选入榜前统一检查，固定队伍评价只回传实际窗口及是否达标。该条件由 Rust 执行，保留的 TS 路线明确拒绝此条件。最高分补齐顺序时沿用原歌曲覆盖和竞技场规则，避免按原曲重新评分。

激奏单曲与多曲按歌曲初始化一次，再由共享队列完整证明；正种子最高分在大卡库、多 COMBO 档位时按完整档位分片，其余按队长分片；LUCK 期望模式按成员集合分片以共享上下文。锁定队长的单曲直接由单 Worker 完成。对手分数模式每曲保留单 Worker 的名次结果，只公开完整迭代后的最终评分。其他多曲按歌曲并行。普通活动的预搜索只展开该分片负责的队长，合法候选仍共享为全局下界。Worker 内复用初始化数据、谱面及转换轨迹。

无 LUCK 的最高分 Top K 分片只先证明主分；私有 `deferScores` 消息用 `pendingScores` 标记尚未补齐的候选。客户端按每曲的成员集合主分边界收集全部同分变体，再并行补齐原生 120 顺序、比较平均分。未补齐的候选不进入公开快照，所有边界候选完整后才报告证明完成；取消保留已完整评分的结果。

桌面 Worker 池最多六个，纯 COMBO 奖励阶段使用同一按设备内存和核心数限制的池。普通挑战 Live 单曲 Top K 在 K 大于一时由单 Worker 完整搜索，保留全局候选下界并避免各队长分片重复准备和展开同分队伍；多曲仍按歌曲并行。激奏奖励的单曲 Top 1 在任务全部为 LUCK／JUST 时共用跨队长上下文；至少 16 个种子的自由队长请求也使用完整分片，小卡库省去通用预搜索，其他请求仍由单 Worker 搜索；未指定奖励方案的纯 COMBO 单曲 Top 1 在一次搜索中比较主奖励、另一项奖励和平均分；加权普通 Live 仍由所有分片分阶段证明这三项；私有 `rewardPhase` 标明分阶段证明范围，各阶段共享已经完整评分的合法候选，三个阶段全部完成后才公开完成证明。激奏中相同成员、留影、玩家和目标的相邻阶段共用完整结算缓存，谱面改变时清空。普通 Live 分片保留各自的队长范围。支持 JSPI 的浏览器在 WASM 时钟暂停期间接收同曲、同阶段的合法候选下界，继续当前分片；其他浏览器在完成片提供更强下界后重新派发仍持有较低下界的运行片。每个分片保留身份，最终仍需全部完成证明。固定种子最高分的晚到预搜索候选也保留到完整结果，并参与后续下界更新。

主线程只编译一次不可变 WASM 模块、序列化一次资料；不超过四首的调用在初始化 Worker 的同时下载所需谱面，多个 Worker 共享最多四张完整谱面载荷。各 Worker 回报其原生四张谱面缓存身份，单独预载只在实际插入时更新淘汰顺序；主线程按逐曲淘汰规则只提供缺少的载荷；更多歌曲仍按 Worker 顺序装载。取消中止进行中的共享下载，保留已经下载完成的固定载荷；失败下载不留在缓存。准备期间收到的合法下界在当前调用开始计算前写入请求，随后继续接收实时下界。各 Worker 将 JSON 直接交给 Rust，独立持有内存、引擎句柄及谱面缓存，Worker 的 JS 侧保留谱面固定来源索引及本次调用载荷。

界面加载、恢复及修改条件时，预取当前已选的不超过四张谱面，沿用同一固定身份下载及缓存。预取只加载谱面，不执行配队；失败由正式请求重试，取消沿用下载生命周期。

客户端还保留一份小批量调用的完整证明：最多四个结果、Top K 不超过五，卡库各不超过 256 张；请求键包含全部输入并仅移除时限和请求身份。私有分片、下界、预搜索与部分完成输入不复用该证明；独立最终结果回调沿用单 Worker 路线。命中时复制完整结果并使用本次请求身份、覆盖率及实际等待时间，调用者不能改写存储的证明。

私有评分包只复用全部 120 顺序已完成的候选；原生端核对完整成长、玩家、约束、目标、请求身份和解析后的谱面，公开结果不含评分包。客户端进入队列时把相对时长归一为绝对截止时间，并清空相对时长；无限截止时间转为 JSON null 后，引擎仍按不限时处理。初始化、WASM 获取、谱面网络和消息处理都可能失败；客户端按请求身份分发错误与结果，预算、取消、部分覆盖及完整结束须保留不同语义。更换 Worker 会丢失其内存状态。

谱面装载按引擎的四张缓存容量模拟请求中的逐曲淘汰；开始时已缓存的谱面若在本次使用前被淘汰，仍需随请求提供。

激奏搜索在有 COMBO 任务的谱面按 `minComboBonus` 基础倍率下限剪枝，以初始 LIFE 和首个 COMBO 成立后的常驻加成为准；后续连击门槛追加进入得分计算。纯 JUST／LUCK 谱面不受此条件限制。结果和进度的 `comboBonus` 使用相同基础口径，条件与模型版本进入缓存和活动推荐任务身份。

普通与激奏的最低分、最高分目标在主分相同时比较平均分；主分保留原值，完整顺序评分按比较需要补齐。固定种子的 LUCK 搜索保留同队长技、同综合力的不同队长站位，随机程序顺序不能按综合力合并；锁定五名成员后，随机上界只准备这些成员的程序；留影全部绑定或不使用留影时，直接完整搜索，省去自由配队的预搜索。名义 LUCK 的平均分与最高分按改变上下文的留影程序分域，Top K 保留预搜索中已精确评分的不同成员队伍；固定种子评分复用原生整数音符前缀。正种子 Max／Min 单曲的抽选投影与无 Rush 投影通过私有 `seedVariant` 并行准备；每份提案仍按全部请求种子评分。正种子最高分先准备 Worker 池；支持实时下界时，任一投影产生足量完整评分候选便开始分片证明，其余情况等待投影返回。另一投影完成时不覆盖已经运行的分片。最高分上界联合匹配五个技能触发位置与随机留影数量；扩展留影数量时复用已覆盖程序的抽选轨迹。区域组件按判定转换轨迹共享最多 16 份技能窗口资料，随机指令数量在当前包络中定价，音符权重仍分别计算。固定种子的确定性上界可用时，跳过仅供旧预搜索读取的权重初始化。固定 COMBO BONUS 按可达倍率限制剩余综合力，成员对偶界沿递归复用舍入顺序相同的前缀。多种子预搜索每个投影只保留请求数量的提案，再按全部请求种子完整评分。COMBO 成员条件每次搜索只解析一次，互不影响的累计留影技能共用原生回放并按归属保留指令。

激奏奖励默认按五名等分玩家的房间评级结算；每个种子与技能顺序先按 battle 阈值评级，再求奖励平均值及评级占比。手动评价的正种子活动收益复用同一逐样本结算，范围与评级占比来自实际样本；零种子保留名义评分。普通单人活动保留个人评级阈值。

显式方案分片保留完整搜索和抽选上下文，不按单一主分下界取消重建。显式 `rewardPlan` 以折算奖励和有序同分层排序，未列出的奖励不参与比较；Rust、进度和分片合并传递精确分数的分子／分母，Top K 仅以已保留的第 K 名收紧边界。自动 CP 折算在分片前按同一折算方案完成挑战曲校准；加载、校准和搜索共用截止时间，未证明的校准不作为完整结果。`cpChallenge` 保留已证明的校准挑战队伍，随进度、分片最终结果和完整响应缓存传递，展示不重复搜索。结果携带当次已解析方案及三项直接收益。旧活动推荐按主奖励、另一项直接奖励、平均分依次排序；纯 JUST 在一次遍历中比较三项，其余模式逐层搜索确切等值组，跨 Worker、跨歌曲和进度合并遵守相同顺序。资源规划按有限 Live Boost 预算的总活动点数排序；按技能顺序的离散 CP 分布结算期望挑战次数与剩余 CP，并在同分组内比较平均分。成员上界按当前尚未跳过的角色组建立后缀，留影匹配复用候选与技能上界。激奏奖励在单次搜索内缓存逐帧上下文，键保留成员顺序、随机种子和技能读取的属性；不在谱面出现的任务技能不进入重放。Rush 留影加成的评分范围由原生持续技能状态机记录，包含离开 Rush 后仍生效的帧。纯 LUCK 奖励上界按成员、留影的原生注册顺序共享等价抽选轨迹，缓存有独立容量上限；纯 JUST 奖励先复用完整顺序系数上界，再进行联合定价与成员支配剪枝。奖励界复用合法触发顺序并优先检查最近生效的对偶参数；仅有主奖励排序时省去未被使用的次奖励界。

完整回放在技能顺序出现差异的事件前共用原生状态，再复制 RNG、LIFE、条件和得分历史继续逐帧执行，仍返回全部 120 顺序。激奏快速评分按原生逐帧顺序记录每颗音符的 LIFE，再处理同帧回血；保留双倍 LIFE 上限和倒地后不能回血的规则。相同回血顺序共用轨迹，普通连击倍率使用激奏判定转换后的判定流。

活动跳过结果同时返回主奖励和另一项奖励的每次数量；加权合计与奖励明细复用这两个结算值，搜索进度与最终结果遵守相同字段契约。

活动目标与评价请求可携带 `eventEffects`，在单次请求内替代参照活动的加成效果；缺省沿用正式活动，空数组明确表示无加成。普通 Live、激奏、跳过及 PT 条件检查使用同一效果，结算表仍由 `eventId` 指定。Rust 入口拒绝手动挑战、资源规划与自动 CP 校准，原始活动资料保持不变。

搜索在热启动前排除必选角色冲突、重复占用留影、空位不足等结构性矛盾。成员／留影定价只计算合法配对，其他成员绑定的留影不进入该成员上界；五个成员全部绑定时，准备域只保留这些位置能够使用的留影。只有必选留影的请求保留原准备域，避免改变物理成员顺序和原生浮点结算。

普通评分与活动分阶段结算的缓存身份包含配队限制，避免卡牌过滤后沿用旧索引。纯 COMBO 在激奏程序相同、普通技能不弱且综合力增量超过原生舍入误差界时，复用支配剪枝；入口加成界保留实体留影的唯一占用。

协议变更核对界面、客户端、Worker 和外部引擎锁；资源身份见 [数据地图](../data/L2-2.md)。验证按 [开发导航](../../../../docs/DEV_GUIDE.md) 选择构建与工具检查；未初始化外部仓库时不能声称验证了引擎。

手动评价可选 `gekiso` 参数携带准确率、指定名次和种子数量，经 `evaluateAll` 进入 Rust 激奏评价；未提供时保留普通评价。评分可返回 `rangeScores`。无 LUCK 谱面的最终结果、奖励结算与手动评价统一使用完整原生回放，枚举全部 120 种技能顺序；最高分搜索按逐顺序严格上界选择需要回放的顺序，再补全入榜队伍。固定种子数量为 0 时保留 LUCK 期望模式，正数枚举种子 0 至 n−1；没有生效随机效果时共用相同结果。含伤害的固定种子评分保留完整 LIFE 回放。

EngineClient 的 phases 提供当前 Worker 阶段，状态变更回调供界面显示准备、加载谱面及计算。WASM 和谱面请求单次最多等待 60 秒，沿用谱面网络／5xx 的三次尝试；搜索时限与资源超时分别处理，默认搜索仍不限时。

纯 COMBO 的私有预搜索只优化主奖励，其结果始终标为未完成完整排序证明。已准备的谱面和 Worker 不消耗预搜索计算片，但仍计入原任务的总时限。支持协作的 Worker 从首个完整评分候选开始并行证明，按当前请求身份同步主奖励、次奖励及均分下界；合法候选独立保留，避免被较弱的分片结果覆盖。每次原生调用清空上一请求的排序下界；显式奖励方案继续使用精确排名协议。

公开设备 SDK 可限制 EngineClient 的 Worker 数量，并为共享谱面装载指定 API 根地址；现有编译模块复用、协作下界及四张谱面缓存协议保持同一实现。

竞技场通过激奏目标的 arena 输入传递联赛、有效属性和三个激奏区间类型；Rust 为每次调用创建规则视图，原始四张谱面缓存不变。成员限制在联赛乐队内，留影保留合法跨乐队范围。shared 目标固定同一队长、成员与留影绑定，对完整曲目集合进行联合平均分搜索；individual 沿用逐曲搜索。联合搜索各歌曲的安全上界与完整评分下界共同决定证明，不能由单曲优胜队伍的集合直接声明最优。

普通与活动联合请求最多使用两个按队长分片的 Worker；激奏联合请求最多使用六个 Worker；共同 COMBO 档位按档位分片，其余按队长分片，低内存设备使用一个。所有分片读取同一完整曲目集合，并以已完整评分的候选共享平均分下界。谱面在主线程以六个下载任务装载一次后共享载荷，调用局部保留完整集合，避免四张长期缓存的淘汰或多个 Worker 重复下载导致漏谱面。规则、聚合方式与曲目集合属于请求和证明缓存身份；结果携带每首歌的完整评分。

普通 Live、激奏、收益与手动评价以请求的 songRules 传递属性和三个区间覆盖；零保留原曲，普通模式不发送隐藏的激奏草稿。Rust 调用局部克隆歌曲与挑战颜色，原始谱面身份和缓存保持不变；冻结结果、时间线及对比身份携带同一投影。

请求 aggregation 为 mean 时，普通 Live、激奏和活动收益共用完整曲目集合及一支固定队伍。普通目标取跨曲平均分，活动目标取跨曲平均奖励；显式奖励方案对每一排序层保留精确分数平均，不加入忽略奖励。自动 CP 价格先按单曲最优挑战校准，再进行联合搜索；普通和活动草稿分别保存聚合方式。

奖励按游戏的 64 位中间乘积结算：每项奖励除以 10000 向零截断后应用 32 位整数上限，概率加权保留精确分数。分子保留符号，分母为正；计算身份包含结算模型版本，浏览器、分片及活动检查点不复用旧公式的证明。资源规划在奖励不单调时保留候选并使用保守上界，只有完整搜索才公开最优证明。

联合激奏按候选实际技能依赖保留 JUST 计数器，以完整顺序系数收紧确定性平均分上界；原生回放仍负责最终评分。普通联合评分在各曲综合力一致时复用共同综合力与加权技能的乘积上界，不同综合力仍逐曲保留安全边界。

大曲池的激奏 Top 1 先完整搜索一首歌取得合法候选，再分配各曲给 Worker 完整评分一次，形成跨曲平均分下界。各搜索分片接收同一已评分阵容、保留全部 COMBO 档位，并省去该物理阵容的重复回放；主线程保留完整候选，所有分片结束且候选达到所声明下界后，联合结果才有完整证明。候选分曲评分未完成时不会发布聚合分数。

累计技能仅在已验证的有限正向范围使用解析上界；负数、无上限、溢出或越界程序保留原生回放与完整搜索，不使用解析支配剪枝。严格活动输入以 64 位中间乘积判定合法范围，网页校验与原生校验一致；有限资源规划使用最终单项 32 位奖励上限构造保守界。计算及活动检查点身份升级后，不复用旧上界的最优证明。

普通演出的累计留影沿用完整回放的 60 Hz 理想判定流；同一帧的判定共同计数，支援技能从成员触发的交付帧起计算自身持续时间。全 PERFECT 与自定义判定共用累计指令时序，判定转换先于累计计数。这是计算器的确定性输入约定，真实设备帧率和手动判定时刻的影响仍待后续验证。

普通判定转换保留配置中的目标判定、独立持续时间及触发来源；常驻 COMBO 辅助不依附成员技能窗口或重置次数，转换后的判定同时进入 COMBO、LIFE、累计与释放条件。低判定释放按首个命中帧中最后匹配音符的谱面时间结束额外加分。存在常驻转换、损伤转换或释放条件的非 AP 搜索使用完整候选评分，停用不适用的解析剪枝。活动检查点的计算身份随此计分口径更新。

累计留影按判定送达帧计数、从该帧起生效，音符按谱面时间计分。时间线请求带 `timing` 时，引擎在凑满各档的判定帧内筛选允许提前 17 ms 且提前后保留原判定的玩家输入，将这些输入提前一帧回放；中间点和滑动触点保留原送达时间。结果返回实际提前的规范判定流索引，技能顺序详情和谱面框选共用这些索引；预览按需读取相同转换器的几何信息，避免同刻不可提前音符被一起框选。

普通最高分新增最佳／最差累计时序选项，通过 `goal.play.cumulativeTiming` 的 `best`／`worst` 传入；原有选项缺省使用名义时序。在固定判定流、谱面计分时间、普通连击与转换窗口的现有模型内，按原生点按、保持与松手、预留划键及自动补判路径枚举 60 Hz 送达帧；组合与连接点按 Trace 路径处理。规范谱面保留判定区域、形状与长条归属，判定区域 Master 来自同一 release 的 options。候选先按整帧选择触点，再处理同步优先级、按下占用与异步判定；短长条结束时强制结算未判起点。选中的极值须通过整帧输入回放，局部必要冲突用于继续划分候选域；输入搜索或内存预算不足时返回失败，不报告已证明的极值。每个技能顺序分别取累计时序最大／最小值，再以顺序中的最高分比较完整队伍候选；相同主分比较同一时序口径的平均分。仅剔除所有受影响累计窗口都同意的单调送达支配，保留窗口冲突分支；新模式停用原数值卡牌支配，继续使用累计上限的安全评分界。请求、最终评价及结果快照携带同一时序参数，不复用另一模式的证明。时间线同时返回最差、名义、最佳时序与可达 17 ms 方案；17 ms 教程不代替完整时序极值。此范围是累计计数的时序优化，不重新优化普通连击、转换和成员技能的触发时刻。
