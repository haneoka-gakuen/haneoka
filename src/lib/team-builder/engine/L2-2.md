## 职责与当前调用链

当前 [界面](../../../lit/team-builder.ts) 创建 [EngineClient](client.ts)，通过 [Worker](worker.ts) 调用锁定的 Rust/WASM 引擎。WASM 由 [构建脚本](../../../../scripts/build/team-builder-engine.mjs) 从 `.dependencies/ournotes-team-builder` 编译到忽略的 `generated/`；引擎内部规则归独立仓库维护。

| 入口 | 责任 |
| --- | --- |
| [client.ts](client.ts) | 主线程请求、多 Worker 分片、进度与快照、取消时替换 Worker |
| [worker.ts](worker.ts) | WASM 装载、release 数据句柄、固定身份的谱面读取、搜索／成长／评价／时间线消息；未评分时原生 null unknownCards 转为空数组 |
| [protocol.ts](protocol.ts) | `EngineCall`、`EngineReply`、停止原因和快照契约 |
| [api.ts](api.ts) | 可序列化输入输出及 TS 评价／搜索实现；不能据此认为浏览器实际走 TS 计算 |
| [master.ts](master.ts)、[box.ts](box.ts) | Master 编译、成员与留影输入和成长状态 |
| [execution.ts](execution.ts)、[merge.ts](merge.ts) | 跨线程预算、完成度、结果比较与分片合并 |

`run` 的可选最终结果回调只用于单 Worker 路径，在合并快照和附加搜索停止标签前提供独立副本。快照、取消、排队超时及分片搜索不会触发此回调；固定队伍选曲据此区分完整评分与搜索候选。

`full/`、Live／Gekiso 与 `api.ts` 保留 TS 实现和类型。修改前先追实际调用者，不能把这些实现、上层 `solver/` 和当前 WASM 路线混为同一个执行入口。

## 状态、失败与验证

激奏单曲与多曲按歌曲初始化一次，再由共享队列完整证明；正种子按队长分片，LUCK 期望模式按成员集合分片以共享上下文。锁定队长的单曲直接由单 Worker 完成。对手分数模式每曲保留单 Worker 的名次结果。其他多曲按歌曲并行。普通活动的预搜索只展开该分片负责的队长，合法候选仍共享为全局下界。Worker 内复用初始化数据、谱面及转换轨迹。

无 LUCK 的最高分 Top K 分片只先证明主分；私有 `deferScores` 消息用 `pendingScores` 标记尚未补齐的候选。客户端按每曲的成员集合主分边界收集全部同分变体，再并行补齐原生 120 顺序、比较平均分。未补齐的候选不进入公开快照，所有边界候选完整后才报告证明完成；取消保留已完整评分的结果。

桌面 Worker 池最多六个，纯 COMBO 奖励阶段最多四个。激奏奖励的单曲 Top 1 在任务全部为 LUCK／JUST 时由单 Worker 完整搜索，共用跨队长上下文；纯 COMBO 的单曲 Top 1 由所有分片依次证明主奖励、另一项奖励和平均分；私有 `rewardPhase` 标明当前证明范围，各阶段共享已经完整评分的合法候选，三个阶段全部完成后才公开完成证明。相同成员、留影、玩家和目标的相邻阶段共用完整结算缓存，谱面改变时清空。其他单曲奖励每个 Worker 分配一片。完成片提供更高的合法主奖励下界时，只重新派发仍持有较低下界的运行片；每个分片保留身份，最终仍需全部完成证明。

Worker 持有编译后的引擎句柄和谱面缓存。客户端进入队列时把相对时长归一为绝对截止时间，并清空相对时长；无限截止时间转为 JSON null 后，引擎仍按不限时处理。初始化、WASM 获取、谱面网络和消息处理都可能失败；客户端按请求身份分发错误与结果，预算、取消、部分覆盖及完整结束须保留不同语义。更换 Worker 会丢失其内存状态。

谱面装载按引擎的四张缓存容量模拟请求中的逐曲淘汰；开始时已缓存的谱面若在本次使用前被淘汰，仍需随请求提供。

激奏搜索在有 COMBO 任务的谱面按 `minComboBonus` 基础倍率下限剪枝，以初始 LIFE 和首个 COMBO 成立后的常驻加成为准；后续连击门槛追加进入得分计算。纯 JUST／LUCK 谱面不受此条件限制。结果和进度的 `comboBonus` 使用相同基础口径，条件与模型版本进入缓存和活动推荐任务身份。

普通与激奏的最低分、最高分目标在主分相同时比较平均分；主分保留原值，完整顺序评分按比较需要补齐。固定种子的 LUCK 搜索保留同队长技、同综合力的不同队长站位，随机程序顺序不能按综合力合并；锁定五名成员后，随机上界只准备这些成员的程序；留影全部绑定或不使用留影时，直接完整搜索，省去自由配队的预搜索。名义 LUCK 的平均分与最高分按改变上下文的留影程序分域，Top K 保留预搜索中已精确评分的不同成员队伍；固定种子评分复用原生整数音符前缀。正种子 Max／Min 单曲的抽选投影与无 Rush 投影通过私有 `seedVariant` 并行准备；每份提案仍按全部请求种子评分，任一投影返回足量候选后即开始完整分片证明，另一投影完成时不覆盖已经运行的分片。最高分上界联合匹配五个技能触发位置与随机留影数量；扩展留影数量时复用已覆盖程序的抽选轨迹。区域组件按判定转换轨迹共享最多 16 份技能窗口资料，随机指令数量在当前包络中定价，音符权重仍分别计算。固定种子的确定性上界可用时，跳过仅供旧预搜索读取的权重初始化。固定 COMBO BONUS 按可达倍率限制剩余综合力，成员对偶界沿递归复用舍入顺序相同的前缀。多种子预搜索每个投影只保留请求数量的提案，再按全部请求种子完整评分。COMBO 成员条件每次搜索只解析一次，互不影响的累计留影技能共用原生回放并按归属保留指令。

激奏奖励默认按五名等分玩家的房间评级结算；每个种子与技能顺序先按 battle 阈值评级，再求奖励平均值及评级占比。手动评价的正种子活动收益复用同一逐样本结算，范围与评级占比来自实际样本；零种子保留名义评分。普通单人活动保留个人评级阈值。

活动推荐按主奖励、另一项直接奖励、平均分依次排序；纯 JUST 在一次遍历中比较三项，其余模式逐层搜索确切等值组，跨 Worker、跨歌曲和进度合并遵守相同顺序。资源规划按有限 Live Boost 预算的总活动点数排序；按技能顺序的离散 CP 分布结算期望挑战次数与剩余 CP，并在同分组内比较平均分。成员上界按当前尚未跳过的角色组建立后缀，留影匹配复用候选与技能上界。激奏奖励在单次搜索内缓存逐帧上下文，键保留成员顺序、随机种子和技能读取的属性；不在谱面出现的任务技能不进入重放。Rush 留影加成的评分范围由原生持续技能状态机记录，包含离开 Rush 后仍生效的帧。纯 LUCK 奖励上界按成员、留影的原生注册顺序共享等价抽选轨迹，缓存有独立容量上限；纯 JUST 奖励先复用完整顺序系数上界，再进行联合定价与成员支配剪枝。奖励界复用合法触发顺序并优先检查最近生效的对偶参数；仅有主奖励排序时省去未被使用的次奖励界。

完整回放在技能顺序出现差异的事件前共用原生状态，再复制 RNG、LIFE、条件和得分历史继续逐帧执行，仍返回全部 120 顺序。激奏快速评分按原生逐帧顺序记录每颗音符的 LIFE，再处理同帧回血；保留双倍 LIFE 上限和倒地后不能回血的规则。相同回血顺序共用轨迹，普通连击倍率使用激奏判定转换后的判定流。

活动跳过结果同时返回主奖励和另一项奖励的每次数量；加权合计与奖励明细复用这两个结算值，搜索进度与最终结果遵守相同字段契约。

协议变更核对界面、客户端、Worker 和外部引擎锁；资源身份见 [数据地图](../data/L2-2.md)。验证按 [开发导航](../../../../docs/DEV_GUIDE.md) 选择构建与工具检查；未初始化外部仓库时不能声称验证了引擎。

手动评价可选 `gekiso` 参数携带准确率、指定名次和种子数量，经 `evaluateAll` 进入 Rust 激奏评价；未提供时保留普通评价。评分可返回 `rangeScores`。无 LUCK 谱面的最终结果、奖励结算与手动评价统一使用完整原生回放，枚举全部 120 种技能顺序；最高分搜索按逐顺序严格上界选择需要回放的顺序，再补全入榜队伍。固定种子数量为 0 时保留 LUCK 期望模式，正数枚举种子 0 至 n−1；没有生效随机效果时共用相同结果。含伤害的固定种子评分保留完整 LIFE 回放。

EngineClient 的 phases 提供当前 Worker 阶段，状态变更回调供界面显示准备、加载谱面及计算。WASM 和谱面请求单次最多等待 60 秒，沿用谱面网络／5xx 的三次尝试；搜索时限与资源超时分别处理，默认搜索仍不限时。
