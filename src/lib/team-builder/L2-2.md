## 跨域契约

[界面](../../lit/team-builder.ts) 持有数据、BoxStore 和 EngineClient，并协调子控制器。`src/lit/team-builder/` 的子模块依赖父组件较大的状态表面，不因拆成文件就成为独立子系统。当前主路径是界面 → EngineClient → WASM Worker；TS solver 及旧存储路径仍存在，应按调用者区分。

数据与谱面按来源身份绑定；跨服合并、规则证据、停止原因和完成度共同影响结果含义。修改公共契约要同时核对界面、Worker API、持久格式与外部引擎。保存失败、证据缺失和搜索中止须保留各自语义。

日服与国际服卡库 JSON 可跨服导入：按原始卡牌 ID 对应，预览只接受目标服目录已收录的卡牌并校验养成数值，确认后只写入目标服卡库；来源服与目标服仍分别保存。目标服后续收录同一卡牌后可重新导入，不自动增加持有。其他授权资料来源及历史编号未建立正式服卡牌对应，不按同号跨服复制；同来源导入仍保留原有身份校验。

本目录内部存在运行时回边，详见 Data；不为地图移动类型或拆分枢纽。验证按 [开发导航](../../../docs/DEV_GUIDE.md)。

MoeNotes `moenotes.card-inventory/1` 当前库存通过 [Box parser](box-import/parser.ts) 适配到 exporter 的现有事实解析与预览，保留未知、冲突和待复核状态；该格式不包含存档链接或观测历史，原有 `moenotes.card-box/1` 备份仍按既有规则读取。

[配队养成对照](team-growth.ts)从冻结的结果输入构造临时单项／升满方案；固定成员、队长、留影绑定及原谱面进行评分，再用原候选范围和约束分别搜索养成前后队伍。新请求丢弃过期截止时间、旧分数和搜索下界，不写入 Box。

优先级批量升满和方案详情共用 EngineClient.run 与最多 256 项的完整响应缓存；缓存按身份、请求和养成输入隔离，未完成结果只用于续算。自动 CP 每个养成方案重新校准，固定队伍比较沿用该方案的校准结果。

养成请求保留歌曲规则和跨曲聚合方式；固定跨曲队伍沿用结果中的完整曲目集合，单曲结果仍固定原谱面。手动评分逐曲比较，不继承自动配队的跨曲聚合设置。

养成优先级将未缓存的完整方案分配给现有 Worker 并行计算，每个方案独立保留原候选、约束、评分条件与最优证明；自动 CP 同样经过完整解析，取消保留各方案的已完成结果与未完成续算状态。
