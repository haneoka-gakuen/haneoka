## 职责与请求入口

[index.ts](index.ts) 是 fetch、scheduled 和 queue 入口，连接静态站点／文档、release 资料、账户社区、资源服务与后台任务。绑定由 [wrangler.jsonc](../wrangler.jsonc) 声明，生成类型不能代替真实环境状态。

`.org` 的 Worker 自定义域与通过 Cloudflare for SaaS 路由接入的 `.com` 共用 Worker、账号和存储。[站点源契约](../src/lib/site-origin.ts) 限定动态入口，认证与邮件操作链接跟随请求源；HTML 资源／操作链接和 Sonolus 文档保持当前域名，canonical 使用当前访问域名。

## 状态与失败边界

匿名 Version 失败通过既有采集回调保存客户端版本与有界上游说明，公开状态和容器日志可区分版本要求与网络拒绝；这些诊断不读取或返回账号响应、凭据及 CDN 授权。

平台账号按 SDK 项目／渠道范围与 UID 原子固定单一归属，多个邮箱别名仅所属账号能进入游戏登录；SDK 认证和游戏登录是两次独立私有请求，归属与加密会话先于游戏请求保存，过期任务与未知结果不重发游戏登录。既有重复 UID 的归属保持待确认。平台账号按 SDK 项目／渠道范围保存独立的长期 UID 绑定，名称、密码和缓存更新不清除；匹配的旧缓存可在有效租约内建立绑定，后续 SDK 结果须在游戏登录前匹配原 UID。该身份及范围不进入管理接口，账号版本或任务期限失效不能读成未绑定身份。

[平台账号存储](official-platform-accounts.ts) 用独立 `OFFICIAL_ACCOUNT_ENCRYPTION_KEY` 加密托管国际服邮箱密码，并保存繁中、英文、韩文的独立初始化状态；[admin.ts](admin.ts) 的 `collector-platform-accounts` 仅管理员可读写，以版本检查更新名称或密码，密码更新清除区域会话并保留玩家 ID；账号表单保存后迁入现有会话或排队账号级登录，只有核验就绪会话进入号池；列表与审计不返回密码或密文。

平台登录租约由 D1 按邮箱账号串行化三个分区，完成写入同时核对任务、账号版本、期限和玩家绑定；已验证区域会话以独立身份上下文加密。[账号任务合同](official-account-jobs.ts)解析独立登录配置并校验容器结果。管理员按账号排队后，全部区域角色先退出选择并排空该玩家在途工作，再执行一次 SDK 验证和有期限的逐区游戏登录／榜单权限核验；新旧角色均验证全部当前目标，只有就绪结果进入现有选择、暂停和健康策略；新用户标记不单独阻止验证。旧版本结果可释放自己的租约但不能更新角色；已托管玩家的旧配置凭据不再回退使用，密码更新即退出可用池。

平台账号另存按 SDK 配置指纹绑定的加密共享会话，后续分区登录先走 `cache.login`；只有明确的失效码允许一次密码重登。缓存读写复用账号版本与登录租约，修改名称保留、修改密码清除；SDK 身份验证通过与区域角色可采集分别保存，不向管理接口返回 SDK 会话。

托管国际服会话在已认证榜单或即时查询明确认证失效后，按账号版本及凭据代保存续期候选，隔离旧凭据并等待至少十五分钟冷却，再复用同一登录、排空和验证链路。权限拒绝、限流、匿名目录失败和网络未知结果不触发续期；暂停、改密及会话替换会阻止过期候选，自动任务开始即消耗该次机会，未知游戏响应不自动重登。重新验证成功后才恢复号池，失败查询不因续期重放。

续期候选先于告警创建持久化，调度失败后由 `ensureScheduled` 恢复；排队执行告警创建失败仅清理同 nonce 且未开始的队列，不删除替代或已执行任务。管理员接口以 `account_queue_failed` 返回 503 并记录失败审计；自动候选保留，其他到期账号不因暂停或未知结果而被重放或长期阻塞。

平台账号列表从区域 DO 只读投影当前号池健康、续期候选与版本绑定的排队／登录状态；只有同账号、版本及玩家的当前状态覆盖角色记录，过期排队与旧版本任务不覆盖。待续期、续期排队、续期中与暂停／冷却分别呈现，读取不写入 DO 或 D1，不返回凭据及内部身份摘要。

列表另返回未定 SDK 归属的脱敏候选组与版本修订，管理员明确选择后经 `sdk-conflicts/{id}/resolve` 确认；成员、版本与在途登录在单条更新中再次检查，数据库触发器同时退役所有成员旧会话并提高账号版本。确认不执行登录，不改派已确定的归属；玩家绑定继续阻止旧手工凭据回退，后续验证仅忽略所选归属的同一 SDK 身份别名，不忽略其他玩家冲突。

[游客存储](official-guest-accounts.ts)保存独立的日服创建任务、加密的原始请求配置与凭据：注册只领取一次，按原 nonce 到达的晚结果仍可保存一次；验证失败保留身份，只有期限内的就绪结果进入实际号池。[游客任务合同](official-guest-jobs.ts)校验阶段、区服、任务／账号身份及原玩家绑定，并用可信配置重建注册结果。日服 DO 排空采集与即时查询后执行注册，先保存身份再排队验证；模糊结果与重启恢复只领取原结果，不重发注册，晚结果不覆盖新任务。管理员的 `collector-guest-accounts` 提供脱敏列表及当前任务元数据、按稳定游客 ID 排队创建／恢复以及版本检查的重新验证，管理面板按任务状态轮询，并在可见页面每 30 秒刷新已验证游客的号池状态。已验证游客按游客与玩家身份匹配当前号池状态，以独立的 `poolStatus` 显示暂停、冷却、采集中与区服停用，保留创建／验证状态及原有操作；读取不写数据库或 DO 状态。托管玩家的旧手工凭据不作为回退使用。

[官方榜单存储](official-ranking-store.ts) 在 `official_ranking_daily` 登记各榜每天最后成功快照；即时窗口替换与定时清理都保护这些引用，保留各自观测时间和覆盖范围。清理经各区服 DO 与归档写入串行处理，索引淘汰同事务登记持久 R2 删除队列，文件删除成功后才确认。[管理员接口](admin.ts) 的 `collector-archives/{region}?day=YYYY-MM-DD` 返回指定日本时间日期的归档目录，仅管理员可读，不返回正文与私有对象路径。

活动单曲、总榜和积分榜的终榜目标保存在 `official_ranking_finals`，按各自结束时间加官方聚合时长到期；区域调度最多每十分钟安排一轮未完成目标，其间继续当前榜单采集。容器使用新鲜 Master／版本和旧活动身份，终榜回调不替换当前目录；首次截止后成功快照固定保留，历史榜的权限拒绝保留待采状态，不计为账号认证拒绝。

活动已采积分窗口参与同一终榜队列；`official_arena_finals` 按竞技场排名统计截止时间保留旧赛季的已采窗口与完整人数目标，人口提示在 D1 独立恢复并重验。两类归档调度轮转，单窗口实际尝试另行排序；截止后成功正文固定保留，旧赛季回调不改当前赛季的目录、人口完成标记与搜索提示。

管理员的 `collector-final-archives/{region}` 读取完整活动／赛季目标摘要及选中目标的逐榜待到期、待补采、已归档状态、截止与原始采集时间；`kind`／`id` 成对指定目标，默认最新截止目标。读取不调度采集，不暴露私有路径、原始定义或搜索提示。

不可变资料对象在 R2；账户和业务状态在 D1；上传、入口包和发布资源使用不同绑定。请求还涉及认证、访问策略、限流、边缘缓存、媒体容器、队列与外部供应方。公共资源读取不等于私有账户读取；各路由执行自己的授权。

fetch 外层提供后台任务上下文、D1 会话、公共读取缓存与成功写入后的失效标记。单独调用内部 handler 不等价于完整入口。队列和定时任务分别调度，错误记录不保证最终处理成功。媒体与审核有独立状态，不能把上传成功等同处理完成。

资源身份、清单和分片由 [Python 生产者](../scripts/core/L2-2.md)、[构建读取](../src/server/L2-2.md) 和 [本地预览](../server/L2.md) 共同消费；演进格式要检查全部实现。验证按 [开发导航](../docs/DEV_GUIDE.md)，本地缺绑定时明确未验收范围。

托管账号支持版本绑定的删除：同事务清除凭据与关联任务，区服／玩家墓碑屏蔽旧静态配置回退。日服可从现有配置迁入原游客身份及加密验证请求；迁入后先独立核验，再参与采集。

国际服登录按账号串行恢复三个区服：D1 batch 互斥覆盖整个链路，SDK 阶段先使该账号全部角色退出选择并排空在途查询，后续逐服仅复用已验证 SDK 会话。后台链保存在 DO，定时任务补回中断的调度；成功验证清除该账号旧认证冷却并保留手工暂停。已有账号可在普通邮箱／密码表单提交时，从私有临时 bootstrap 迁入有效会话与原 SDK 设备 ID，不执行新的登录。

临时会话迁移在全部区域角色就绪、旧采集／查询退出后，按配置摘要一次性清除托管账号旧认证冷却；保留手工暂停，后续正常失败仍按原策略冷却。日服只自动迁入已有成功采集记录的原游客身份。

采集失败保留脱敏异常类型与文件／行号，便于定位容器 500；私有登录配置可暂停自动续期，现有有效会话仍用于只读查询。

区域 DO 初始化时恢复容器内部服务令牌，冷启动与定时采集共用同一认证配置。调度端完整读取容器控制响应；容器服务的 5xx 按短间隔重试，不增加游戏账号的认证失败或冷却。

账号的最近成功时间同时记录已保存的玩家资料和乐曲榜查询；只读查询占用账号时，健康状态仍反映实际成功响应。

活动目录内容未变时复用原 R2 正文，最新核对时间从 D1 读取。结算目标只在活动／赛季定义变化时批量登记；新增排名窗口由各自采集写入路径登记，避免每轮重写全部既有目标。

人数探测回调按任务能力接入，确认检查点及账号健康后不写 R2／D1 排名历史；完整人数和正式排名窗口继续保存。窗口巡回游标只随成功保存的计划窗口前进。公共状态的 `sampling` 区分人数探测和已保存窗口计数。

人数快照的后台目标为二十分钟，提前五分钟让出无人请求的深页巡回预算，并在有界补齐轮次内加快调度，为计算与重试留出余量。榜首与显式窗口需求继续执行，补齐后恢复通常节奏；赛季开放前不执行人数预热。

即时查询以持久告警恢复调度，保留未执行的需求，只退役实际尝试的子集；批次完成时原子更新队列和健康状态，公共 `demand` 状态给出有效排队数、重试时间和脱敏失败。只读任务到期释放自己的租约；容器、回调及网络暂态故障按 15–120 秒恢复，不升级为账号认证暂停。升级时一次性清除没有明确认证拒绝的旧只读冷却，保留手工暂停、认证拒绝与限流冷却。

人数任务按最后完整快照从旧到新排序，单组连续三轮未完成后让下一组先执行。`populationProgress` 公开各组最近工作时间、完整快照时间、未完成数量以及预算耗尽／边界变化原因；进度提示不替代完整人数。

官方观测正文在同一 D1 batch 内与索引持久提交，立即可读；每区一分钟窗口按最多 2 MiB 封装不可变 R2 批次，超过 256 KiB 的单份正文沿用独立 R2 对象。定时调度先恢复成熟批次，R2 成功后才原子移除暂存；每区最多积压 64 个批次。数字历史、原始时间及单份正文哈希不变；归档引用按观测保护索引，回收按全部正文引用保护共享对象。

各区服的采集轮次至少间隔五分钟，与号池账号数量无关；补采、终榜和部署恢复的旧调度共用该限制，玩家与歌曲即时查询保留独立短任务。同一区服、榜单与对齐百名区间的实际读取共用滚动 300 秒准入窗口，常规采集、显式需求及人数探测共用采集宿主上区域对象的持久缓存；缓存命中不产生新观测或推进原始时间，探测结果可按需提升为已存排名窗口。失败或未完成的准入保留到窗口结束；重试回执按请求身份固定。终榜只复用截止后观测，截止前缓存会延后终榜读取。积分榜首窗同时投影旧点数榜接口，不重复请求同一官方区间。

窗口准入首次接管沿用已存观测时刻；常规下一轮在五分钟区域调度内按最早的当前榜首窗口到期时间安排，避免缓存命中后再多等一整轮。

榜单顺带采集的玩家资料在 150 秒内内容相同时合并写入；内容变化即时保存，独立玩家查询仍按原路径立即保存。

官方正文读取兼容原有 JSON 与 gzip，解压结果限制在 8 MiB，仍按原始正文哈希核验。压缩只改变 R2 存储封装，原始观测时间、正文与哈希保持不变；编码切换先部署兼容读取器，再启用压缩写入。

存储维护先扫描合并批次，再扫描旧格式，每页最多 500 个对象，一轮完成后等待一天。仅处理采集器生成的规范 JSON 路径；未知文件、原始名片图片和旧供应方归档保留。超过一天且无任何引用的对象进入持久删除队列，五分钟后复查目录、历史、每日／终榜、排名元数据和暂存引用再回收。共享对象以最后一次成员退役时刻计算宽限期。存量压缩每区最多 64 份／32 MiB／20 秒，区服顺序执行，不占游戏采集队列。已压缩批次只在超过十二小时且退役引用变化后复核；精简须同时减少至少四分之一原始封装及 64 KiB 已存字节，防止小收益重复写入。

普通歌榜只按需、每区每分钟至多一批、每批一首、三十秒预算，玩家／名片需求优先；仅在至少两个账号闲置时使用一个，并始终另留一个闲置账号给活动／竞技场，否则延后；失败退避与玩家／名片需求分开，不扩大定期巡回范围。
