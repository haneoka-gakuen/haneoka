# UI translation maintenance

The five `public/i18n/*.json` files are the authoritative UI catalogs. Keep their semantic schema and interpolation parameters identical. Preserve authored translations; content-language fallback and UI-language fallback remain separate.

Use this top-level order: `common`, `navigation`, `settings`, `home`, `catalog`, `story`, `media`, `tools`, `editors`, `account`, `community`, `legal`, `admin`. Add text to its owning domain. A new tool belongs under `tools`; it does not go at the start of the file. Actions, states, shared fields and layout labels have separate `common` groups. Game entity fields belong to their catalog domain, and media controls belong to media. Avoid flat root labels and mixed compatibility buckets.

Call translation APIs with complete canonical paths. Local control or metadata identifiers may use an explicit finite map to those paths. Keep resource IDs, data fields, route kinds, query parameters and file names separate from message paths. `LABEL_ENTRIES` keeps component identifiers on the left and canonical translation paths on the right. A page enum used for component dispatch requires an explicit group-path mapping; changing the enum to a translation path changes its other consumers.

Register feature paths and dependencies in `src/i18n/namespaces.ts`. The shared dependency closure is used by SSR, independently requested bundles and client loads. Global shell controls must have their small translation projection available on every route. Feature projections select declared paths; they do not inject all catalog scalar values. Namespace content hashes and Japanese fallback provenance remain owned by the existing `@haneoka/i18n` runtime and server/client adapters.

Use the existing TypeScript translation-shape contract, build/check commands and real application behavior when verifying changes. Update every direct, template, enum, group, SSR and client consumer when moving a message. Source migration records belong in the accompanying mapping report; do not retain a permanent legacy-key alias layer.
