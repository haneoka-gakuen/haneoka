# 本地服务与采集 · L2

上级：[地图](../L1.md)。

## 职责与入口

[ranking-collector-official](ranking-collector-official/README.md) 是独立 Python 四服榜单采集器；配置式下载与校验 Master，生成活动目标，保存单曲／总榜观测，并提供只读新鲜度接口。Windows、Linux 和 macOS 共用 Python TLS／HTTP/2、进程锁与离线安装入口；日服匿名 Version 动态提供 CDN 密码，客户端用户名与解码参数由外置配置提供，catalog 与采样共用目录落库和换期检查。国际服通过官方 GetServerList 发现分区 CDN；[分区合同](ranking-collector-official/core/regions.py) 固定 API、凭据区服和协议描述，每个运行目录保存独立目录、换期水位及历史。

工具内部由 [HTTP/2 传输](ranking-collector-official/core/http2.py)、[跨平台进程锁](ranking-collector-official/core/process_lock.py)和[离线安装](ranking-collector-official/setup.py)分别负责官方请求、进程协调及固定依赖安装。

日服 API 的 TLS 握手固定为兼容网关的 TLS 1.2／ECDHE 配置；国际服和 CDN 继续使用各自默认 TLS 协商。证书与主机名验证保持开启，匿名版本请求的拒绝与账号认证失败分别处理。

云端适配器还消费 Worker 保留的活动与竞技场终榜目标：沿用新鲜 Master／版本检查，按旧活动或赛季身份和本轮请求期限采样截止后的榜单、已采窗口与完整人数；人口提示重验后发布，当前目录与归档目标在 Worker 中分别持久化。

[账号池 CLI](ranking-collector-official/account-pool.mjs)兼容原 T62 SQLite/AES-GCM 私密注册表，管理 origin 绑定、启停、区域选择、租约与认证暂停；[有界查询](ranking-collector-official/core/pool_query.py)复用同服官方 Master 和 Python Sampler，导出公开单曲／总榜及私密云配置，不执行登录或注册。

[国际服邮箱协议](ranking-collector-official/core/platform_login.py)执行官方 SDK RSA 挑战、密码加密、表单签名、邮箱登录及 `cache.login` 会话校验；渠道参数由外置 profile 提供，设备身份按平台账号固定。[区域游戏登录](ranking-collector-official/core/player_login.py)消费 SDK 会话和同服描述，使用无历史落盘的 PlayerLogin 取得角色凭据并核对已绑定玩家。[账号任务](ranking-collector-official/core/account_job.py)先复用共享 SDK 会话，仅明确失效时重新验证密码，再从新鲜官方目录验证全部当前活动目标及各竞技场段位的榜首窗口，新旧角色通过同一套权限验证后才就绪；通过独立认证的 Container `/account-sdk` 与 `/account-game` 分段返回私密结果，SDK 归属确认并保存会话后才执行游戏登录，与采集、按需查询互斥执行，不写密码或会话回执。

[日服游客注册协议](ranking-collector-official/core/guest_registration.py)以显式客户端版本和可选设备／初始分组配置发送一次 `PlayerService/Register`，返回私密凭据及精确保留的 profile ID；不重试、不写回执，身份由 Worker 加密保存，验证成功后才进入号池。

[游客两阶段任务](ranking-collector-official/core/guest_job.py)通过认证的 Container `/guest-job` 分开执行一次注册和已保存凭据的只读验证；注册阶段先检查新鲜目录，再立即返回新身份，后续验证复用账号任务的当前榜单检查，按日服描述省略国际服专有资源版本。`/guest-result/{runId}` 只读取进程内已完成的注册结果；未知执行结果不再次注册。Worker 调度接收管理员创建、找回及重新验证任务。

[云端入口](ranking-collector-official/cloud.py)与[单轮适配器](ranking-collector-official/core/cloud_job.py)在独立 Cloudflare Container 中复用官方目录及请求协议；每轮通过获认证的 Worker 回调提交目录、请求检查点及观测，再由区域 Durable Object 调度并持久保存运行控制及固定白名单的失败阶段／状态码。进程内结果缓存仅淘汰过期任务，保留有效请求的结果及未知执行标记，避免后续任务挤掉重复执行保护。临时目录只存本轮私有配置与回执，历史正文、游标和认证暂停由云端存储负责；容器本地 SQLite 不参与云端读写。设置远端 origin 后，同一入口经 [Docker 部署](ranking-collector-official/deploy/compose.yaml)在自有主机运行，日服流量走回环日本出口，采集任务异步受理并以回调报告失败。

[按需读取](ranking-collector-official/core/demand.py)在同一轮次内补玩家资料与乐曲榜单，被拒绝时只结束本轮按需读取，不影响账号；[Arena 采样](ranking-collector-official/core/arena.py)按任务能力复用同一身份、版本及请求预算，先采活动榜与五个联赛榜首，再补兴趣／巡回窗口和人数统计；中间探测页按任务能力只确认检查点，完整人数与正式窗口仍保存。人口使用同服开放 LP 阈值、持久搜索提示与五分钟内读到的边界，人数按完整快照从旧到新续算，连续未完成时有界轮转；提示记录预算或边界变化，未完成不发布完整人数。缺少 Arena 能力的旧任务仍仅获取原三张活动表和活动榜单。

[存储](ranking-collector-official/core/history.py)在 SQLite 中原子绑定运行分区，拒绝跨服或混服历史；旧日服数据只读检查不迁移，写入时收录其分区身份。[只读接口](ranking-collector-official/core/api.py)按数据库及状态分区校验请求，错误分区 URL 不读取其他服历史。[分区合同](ranking-collector-official/core/regions.py)集中定义固定 API、同服凭据来源、协议描述和 CDN 发现规则。

[preview.ts](preview.ts) 为跨服社区谱面／故事及阅读播放子页提供规范空壳、旧地址重定向和逐实体元数据／ETag，启动本地 Node HTTP 服务，提供构建后的静态页面、release-backed 目录／媒体／Sonolus，以及受约束的供应方代理。[releaseWorkspace.ts](releaseWorkspace.ts) 解析本地 current 指针、release 身份和安全文件路径。

输入为构建输出、环境选择及授权的本地 release；输出为本地 HTTP 响应。服务会读文件、监听端口，并可向配置的供应方／Worker 发请求。缺 `current.json` 或本地资源时，源码克隆本身不能提供完整目录。

HTML 响应从同一构建目录的 `build.json` 注入更新基准；存储文档及共享脚本不携带冻结发布的全局身份。
`web` 是浏览器更新基准；有 `publication` 时，预览核对本地最终引用摘要。旧格式继续使用原 Web 基准。

这里与 [src/server](../src/server/L2-2.md) 的构建期 SSR、[worker](../worker/L2.md) 的生产绑定分别维护。代理的认证／请求头边界须保留，不能把本地预览视为完整生产替身。

改资源身份、分片与地址核对 [共享契约](../scripts/core/L2-2.md)、Worker 和构建读取。启动和验证命令见 [开发导航](../docs/DEV_GUIDE.md)。

官方采集容器的未捕获异常返回脱敏失败类型和源码文件／行号，Worker 保存同一诊断字段；不记录异常正文、凭据或请求体。

官方容器通过带能力的窗口准入回调复用区域 DO 中 150 秒内的榜单观测；本轮强制人数复核同样沿用此窗口，跨轮次和容器重启不重读。缓存暂不可用时延期该窗口并继续其他榜单；收到复用结果时保留其原始时间和身份。

[采集宿主](collector-host/src/main.ts)在自有主机上运行区域采集对象：同一套采集代码配合[本地存储](collector-host/src/storage.ts)、[调度](collector-host/src/containers.ts)、[本地官方库与变更队列](collector-host/src/d1.ts)和[经 Worker 的对象存储](collector-host/src/r2.ts)；按行把变更批量同步到 D1，网站只读 D1。
